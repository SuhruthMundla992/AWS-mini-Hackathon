# Course Translator

Turn the courses you've taken into the exact skills a specific company's postings ask for —
in under a minute, with no account and nothing stored.

A student (1) picks their school, (2) checks the courses they've taken from a dropdown
**grouped by level** (100-level, 200-level, …), (3) picks a **target company** from a list of
10 big-tech names, (4) chooses **Internship or Full-time**, and (5) picks a **role function**
(e.g. Software Engineer). The tool then **scans that company's live job postings right now**,
keeps only the ones matching the role + employment type, and shows which skills from the chosen
courses those postings actually ask for — each backed by a sentence from the school's **public
course catalog** and ranked by how often this company's matching postings mention it. They also
get two paste-ready blocks — Relevant Coursework and Skills — in plain text or LaTeX.

Example: *Palantir · Internship · Software Engineer* → 34 open postings scanned → "Data
structures" appears in 100% of them, "Computer security" in 62%.

## Why it's trustworthy

- Every skill shown is tied to a real catalog sentence (open "Why this skill?" to read it).
  No skill is emitted unless its name appears in the catalog text.
- Every demand percentage is **counted from live job postings**, never generated by the LLM.
- The LLM only ever polishes wording; all numbers come from data. Works fully offline.

## Setup

```bash
npm install
```

Requires Node.js 22+.

## Run

```bash
npm start
```

Then open http://localhost:3002

## Test

```bash
npm test
```

Runs the `node --test` suite in `test/`. Tests never hit the network (they use fixtures).

## Build real demand data

The demand percentages come from counting skills across live job postings. To refresh them:

```bash
npm run build-demand
```

This fetches postings for a curated company list, classifies each into a role, counts skills,
and writes `data/demand.json`. It also updates the committed `seed/demand.fallback.json` so the
tool still shows real (if slightly older) numbers when run offline. If `data/demand.json` is
absent, the app falls back to the committed snapshot automatically.

## Add a school

Catalog data lives in `seed/catalogs/<schoolId>.json`. To pull a new school from its public
catalog:

```bash
npm run scrape-catalog -- <catalog-url> <dept-code> <schoolId>
```

This extracts `{code, title, description}` into `seed/catalogs/<schoolId>.json`. It is
best-effort and respects the source's public catalog; always spot-check the output. TAMU
(`seed/catalogs/tamu.json`) ships seeded. See `scripts/scrape-catalog.js` for details.

## Environment variables

| Variable   | Default   | Purpose |
|------------|-----------|---------|
| `PORT`     | `3002`    | Port the server listens on. |
| `LLM_MODE` | `offline` | `offline` uses deterministic templates for all wording (default, needs no credentials). Set to `bedrock` to let Amazon Bedrock polish phrasing when AWS credentials are available. Numbers never come from the LLM in either mode. |

## Privacy

No account, no sign-in. What you type is processed in memory for the one request and is not
stored.

## Project layout

```
public/      static UI — index.html, app.js, styles.css (this is the frontend)
src/         Express server + translation engine
seed/        committed real catalog data + demand fallback snapshot
scripts/     catalog scraper + demand builder
test/        node --test suite (no network)
data/        gitignored, regenerable: demand index + flag queue
```
